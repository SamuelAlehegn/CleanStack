# AI-friendly conventions

CleanStack generates every project with a documentation layer written for two
readers at once: humans and AI coding agents (Claude Code, Cursor, GitHub
Copilot, Codex, Windsurf, and similar). The goal is that follow-up code —
whether written by a person or generated by a model — looks like it belongs to
the project.

## What is generated

```text
demo/
├── AGENTS.md                 Entry point that AI coding agents read automatically
├── ARCHITECTURE.md           Full-stack architecture for humans and agents
├── .ai/
│   ├── README.md             What this folder is and how to use it
│   └── rules/
│       ├── architecture.md       Layers and allowed dependencies
│       ├── naming-conventions.md The naming contract for every artifact
│       ├── protected-regions.md  How to edit generated files safely
│       └── adding-an-entity.md   Workflow for new entities and features
├── demo-backend/             Spring Boot API (own README.md and ARCHITECTURE.md)
└── demo-ui/                  Angular application
```

| File                              | Purpose                                                                                                                                        |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `AGENTS.md`                       | The agent entry point. Most AI coding tools pick this file up automatically and follow the golden rules, which point into `.ai/`.              |
| `ARCHITECTURE.md`                 | Workspace-level architecture: layout, both sides, end-to-end request flow, and schema-change policy. Links to the backend `ARCHITECTURE.md`.   |
| `.ai/rules/architecture.md`       | Package responsibilities and dependency directions for the backend and the frontend.                                                           |
| `.ai/rules/naming-conventions.md` | Every derived artifact name for a sample `Product` entity — Java classes, DTOs, migrations, Angular files, routes, REST paths, database names. |
| `.ai/rules/protected-regions.md`  | Marker format and the editing rules that keep user code alive across `cleanstack regenerate`.                                                  |
| `.ai/rules/adding-an-entity.md`   | Descriptor-first workflow plus a table of where follow-up code belongs.                                                                        |

## Why it works

- **One naming contract.** Agents copy the conventions they see. When every
  artifact name is derived from the entity name by a documented rule, a model
  asked to add a `CancelOrder` use case writes `service/CancelOrderUseCase.java`
  instead of `orderCancellationHelper.ts`.
- **Generated code is off-limits.** The protected-regions rules tell agents to
  put their work inside `<cleanstack:user-code>` regions, so their output
  survives regeneration instead of being silently destroyed.
- **Generation over handwriting.** The adding-an-entity workflow routes agents
  through `cleanstack entity <Name>` instead of letting them hand-write CRUD
  code that would drift from the templates.
- **Committed and shared.** The folder is part of the generated repository, so
  every teammate and every agent session starts from the same rules.

## Working with the rules

The rules are regenerated with the rest of the project. Each file ends with a
`<cleanstack:user-code>` region; put project-specific conventions there and
`cleanstack regenerate` merges them back instead of overwriting them:

```bash
cleanstack regenerate            # refresh skeleton docs, keep your notes
cleanstack regenerate --dry-run  # preview first
```

## Customizing for all future projects

The files come from the built-in `project` template pack. Override it like any
other pack:

```bash
cleanstack templates init project
# edit .cleanstack/templates/project/root/.ai/rules/naming-conventions.md.hbs
cleanstack templates diff project
```

See [Templates](TEMPLATES.md) for the override chain, and
[Protected regions](protected-regions.md) for the marker contract referenced by
`.ai/rules/protected-regions.md`.
